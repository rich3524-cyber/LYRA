# LYRA — Internal Alpha Testing Checklist

**Alpha start:** 21 Jul 2026  
**Alpha end (target):** ~4 Aug 2026 (2 weeks)  
**Goal:** Confirm core workflows hold up under real, varied use — not just "worked once" — before wider release. Pay attention to silent failures as much as visible ones; every major bug found in the pre-alpha pass was silent on the surface.

How to use this: check items off as you go. If something fails, note it inline (`- [ ] ~~item~~ ❌ description of what broke`) rather than deleting the line — a record of what broke and when is more useful than a clean checklist.

Aspect-ratio hints shown per tab (TikTok: "9:16 vertical · one video file only", LinkedIn: "1.91:1 landscape or 1:1 square · one video file only", etc.).

## Week 2 (28 Jul–3 Aug) — AI comment response & Inbox

- [x] Test **No reply** mode — confirm comments come in but nothing gets auto-replied ✅ 21 Jul 2026 (ITWM) — DB-confirmed `aiResponseMode: OFF`; today's LinkedIn/Facebook/Instagram comments all came in correctly with zero auto-replies, as expected for this mode
- [x] Test **Post with approval** mode — confirm AI drafts a reply, it sits pending, and approving it actually sends ✅ 22 Jul 2026, per Richard's direct confirmation — AI drafted a reply, sat pending, and approving it sent successfully. **But** a real self-reply loop turned up right after: the approved reply got picked back up as a "new" incoming comment (its authorName was literally identical to the connected account's own name), and the AI drafted a reply to its own reply. Root cause: of the three separate places that ingest comments (real-time webhook, manual Sync button, automatic cron), only the manual Sync button had gotten a self-comment filter (added 21 Jul) — the automatic cron, which runs unattended far more often than someone clicks Sync, had no self-comment filtering at all. Fixed by adding the same filter there; the one spurious pending comment was manually marked IGNORED. **Recurred a third time, 23 Jul 2026:** a manual reply to an escalated comment came back through the real-time webhook (the one path that DOES have a self-comment check) and still wasn't caught — its two fallback checks (native-id match, username match) turned out to be structurally broken for Zernio-connected accounts specifically: `account.platformId` stores Zernio's own internal account id for these accounts, not the native platform id, so it can never match a live delivery's native `author.id`; Facebook Pages also generally have no "username" the way personal profiles do. Fixed by adding the same name-match fallback the sync route and cron already use (commit `387d47e`).
- [x] Test switching between autonomy modes mid-stream (e.g. a comment arrives, then you change the mode) — confirm no double-replies or dropped comments ✅ ~23 Jul 2026 (ITWM) — per Richard's direct confirmation: switched autonomy mode while a comment was in-flight, no double-replies appeared and no comments were dropped
- [x] Leave a genuinely negative/hostile test comment — check whether Crisis Aware detection triggers as expected (auto-pause posting, audit trail entry created) ✅ 23 Jul 2026 (ITWM) — first attempt (added an `ALWAYS_ESCALATE` guardrail keyword "lawsuit", left a matching Facebook comment) did not trigger after 8+ minutes; root-caused to Crisis Aware never being wired into the real-time webhook ingestion path (only the polling cron, which is separately broken for Facebook on a Meta permission error) — fixed (commit `caf414c`). Re-tested after deploy: deleted and re-posted the comment, confirmed via DB — `crisisActive: true`, `CrisisEvent` created with `triggerType: "KEYWORD_MATCH"` correctly linked to the new comment, and Richard confirmed the in-app crisis banner appeared. **Known limitation, not yet tested:** SENTIMENT_SPIKE (3+ negative comments in one batch) still only works via the polling cron, which needs its own separate re-test once the Facebook permission issue is resolved. **Separately confirmed a real UX gap while investigating:** Crisis Aware's escalation is in-app only (banner + auto-pause) — there is no email/notification of any kind anywhere in the codebase, so nobody is alerted unless they happen to have LYRA open. Flagged for the "build it out properly" follow-up work.
